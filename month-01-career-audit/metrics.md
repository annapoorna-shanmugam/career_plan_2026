# Metrics & Evidence Bank

Keep concrete numbers here so they can later be reused in resumes, promotion narratives and interview stories.

| Metric | Value | Context |
|---|---:|---|
| Transaction volume | ~20M/day | Payment platform / migration |
| Total APIs in migration | 30 | Overall team effort |
| APIs personally contributed to | ~10 | C++ → Java migration |
| Transaction models consolidated | 2 | Recovery + Correction |
| Legacy production issues | ~20/sprint | C++ system |
| Post-migration issues | <5/week, sometimes 0 | Java + FT |
| FT passing rate | >97% | Java services |
| Test coverage | >80% | Java services |
| Release capability | Within a day | Java services |

## Evidence Rules

- Never turn an estimate into a precise number.
- Distinguish team-level metrics from personal contribution.
- Keep before/after periods comparable where possible.
- If a number cannot be verified, label it as approximate or TBD.
